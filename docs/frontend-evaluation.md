# 桌面 UI 与资源预算评估

日期：2026-09-08。状态：候选研究与评测计划，尚未完成框架间性能测试。

## 目标与当前结论

Resona 对标 TeamSpeak 的常驻语音使用场景：游戏过程中保持低 CPU、低内存和较小 GPU 干扰。外观服务于清晰、高效的交流，不以持续动画或大面积模糊换取视觉效果。目前语音尚未接入，不能宣称资源占用或通话性能已经优于 TS3。

当前 Wails v2 + React 是已可运行的验证客户端，保留为基线。下一步先测量，再用相同内容验证 Rust 原生 UI；暂不因语言名称或宣传数字全面迁移。ADR-0002 仍有效，替换框架需要新的 ADR 和可复现结果。

## 候选

| 方案 | 渲染与现有 Go 核心关系 | 评估重点 |
| --- | --- | --- |
| Wails + React（当前） | Go 与系统 WebView；业务代码可直接复用 | 全进程开销、增量状态、长列表渲染、图片桥接成本 |
| Tauri + Web UI | Rust 宿主与系统 WebView；保留 Go 时需另做集成 | 与当前仍属相近渲染路线，不作为降低 WebView 固定成本的首选实验 |
| GPUI + GPUI Kit | Rust 自行渲染；Go 核心通过明确边界接入 | 精细外观、长列表、文本输入、后台重绘、GPU 驱动与多平台交付 |
| Slint + Rust | 声明式 UI 编译与原生渲染；Go 非官方列出的语言集成 | 低占用、设计迭代、输入与无障碍、Go 集成及所选许可条件 |
| Iced | Rust 原生 GUI，提供 GPU 与软件渲染路径 | 常规组件与自定义外观；上游仍标记实验性，需验证完整桌面流程 |

优先制作 GPUI + GPUI Kit 的界面小样，Slint 为低占用对照候选；若平台或文本输入验证失败，再决定是否扩大 Iced 等候选范围。以上排序是本项目的工程判断，不是性能排名。GPU 加速、Rust 无 GC、较小安装包都不能单独证明后台省电或整体占用更低。

## Go 与 Rust 的职责

Go 继续负责连接、身份、权限语义、状态归并、缓存和未来机器人。原生 GUI 小样先消费与现有界面相同的本地测试数据，不必立即引入跨语言协议。

候选通过 UI 与资源测试后，才验证 Go 核心与 Rust GUI 的集成：可比较进程内 C ABI 与子进程本地 IPC。前者需解决线程、回调和内存所有权；后者增加进程及序列化开销，但便于独立构建和隔离。评测必须把 Go 核心与 GUI 的总成本计入，不能只展示 Rust 窗口的占用。

不为换 GUI 先重写 Go 协议栈，也不预建大型通用 RPC 框架。音频采集、编码、抖动缓冲和混音属于独立实时路径，不能逐帧经 GUI JSON 桥传递。

## 先处理可见的成本

目前 GUI 每秒获取完整 Workspace，包含频道、成员、最多 500 条消息和图标 data URL。即使网络图标已缓存，重复序列化与前端解析仍可能耗费 CPU 和内存。应先量化以下项目，再按实测热点实施：

1. 版本化状态或增量事件，避免无变化时重复传输完整快照；保留重同步与迟到事件隔离。
2. 图标资源与高频状态分离，避免相同 base64 数据持续跨桥传递。
3. 长频道和消息列表按实际规模虚拟化，保持输入法、可访问性和滚动位置正确。
4. 最小化或后台时停止无必要的视图刷新；网络保活和音频工作继续按各自需要运行。
5. 模糊仅在局部使用，比较开关效果时的 GPU 和功耗；无变化时不持续播放动画。

上述是待测与待实现项，不表示当前已经完成。

## 同负载验证

使用 release 构建，固定操作系统、硬件、分辨率和缩放。macOS 可先做开发验证，Windows 是游戏常驻的重要验收平台，必须独立验证；不能从 macOS WebKit 结果推断 Windows WebView2 的表现。

| 场景 | 记录 |
| --- | --- |
| 冷启动与重复启动 | 首个可操作画面耗时、峰值和稳定内存 |
| 无连接静置、已连接静置、最小化 | CPU 平均与尖峰、唤醒、GPU 使用、稳定内存 |
| 相同频道 / 成员 / 500 条历史 | 打开、切换、滚动的帧耗时与分配增长 |
| 中文输入、长消息、图标冷暖缓存 | 输入响应、正确性、下载次数、界面停顿 |
| 连续消息与连接 / 断开循环 | 长时间内存趋势、资源回收、线程和句柄趋势 |
| 未来语音期间与游戏并行 | 编解码和混音开销、延迟 / 丢帧、游戏帧时间影响 |

内存记录应包含主程序、WebView / GPU 辅助进程及 Go 核心。区分 RSS、共享内存与平台实际占用指标，不能简单把共享页多次相加。记录样本、次数、持续时间与统计方式，不拿空窗口和完整客户端作等价比较。

TS3 对比固定官方客户端版本与同等可用功能、同样连接场景；当前文字切片只能证明对应部分。先形成基线，再制定数字预算。原生候选只有在相关场景稳定降低总资源占用，且输入、权限提示、键盘操作和多平台打包通过时，才进入迁移决策。

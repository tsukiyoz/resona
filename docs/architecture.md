# 架构设计

2026-09-14 控制协议更新：使用 Protobuf schema 和生成 Go 消息替换 CBOR，生成对象仅位于 `internal/nativewire/pb` 与 wire 映射边界，业务状态仍为普通 Go 值。语音固定头和 Opus 不变；QUIC ALPN 为 `resona-exp-2`，Noise 握手为 `resona-noise-exp-3`，匹配升级且不回退。生成入口 `make generate` / `go generate ./internal/nativewire/pb`；正式构建不要求 protoc。性能实测为解码较快、部分消息更大且分配更多，详见 ADR-0021 与 `test/controlcodec`。

2026-09-12：用户选择 Noise UDP 作为原生主实验，QUIC 保留显式对照。`internal/noiseudp` 负责 NK 握手、认证数据报、防重放、有界可靠控制和生命周期，`internal/nativewire` 提供两种传输的最小共同接口。书签使用独立 `serverPublicKey`，不复用证书指纹；server 默认 `--transport noise`。语音仍在 Go core 编解码。见 [ADR-0019](adr/0019-noise-udp.md)。

## 产品与部署边界

Resona 首先是本地桌面 GUI 应用。使用 Wails v2 承载 React/TypeScript 界面与 Go 应用服务，正式桌面操作经绑定方法进入 Go，不必经过一个独立 HTTP 控制服务。

新增 `desktop/` GPUI 原生实验入口与 `cmd/resona-core` 子进程，通过继承管道的 NDJSON 交换控制和变化快照。`internal/desktopipc` 管理请求、事件和进程关闭，`internal/audio` 持有实际音频路径。原生界面不沿用 Wails 每秒轮询，也不传输逐帧音频。Wails 保留为验收与性能基线；详见 ADR-0011、ADR-0012。

长期产品是自有客户端、服务端和 Go 生态，TS3 是第一个兼容适配器，不是整个领域模型的定义。未来客户端和服务端分别验证 TS 兼容边界，再按实际需要扩展能力。自研协议是一种可能的演进路径，需要以延迟、可靠性、功能限制或维护成本等测量结果支撑，暂不预建第二套协议或庞大通用接口。

根目录保留 Wails 标准入口与资源嵌入，单 Go module 为 `github.com/tsukiyoz/resona`。这是工具链兼容选择，不代表业务代码放在 main 包。未来真正增加机器人/服务端时再决定入口布局和构建方式。

## 当前职责

| 位置 | 职责 | 依赖限制 |
| --- | --- | --- |
| `main.go` / `app.go` | 窗口、生命周期、Go 与 GUI 桥接 | 不实现 TS3 协议 |
| `internal/client` | 本地预览、真实连接生命周期、状态快照、输入校验 | 不导入 Wails、React 或具体协议库 |
| `internal/protocol/ts3` | 持久身份、TS3 连接、频道移动与文字、事件归并、spacer 和图标资源适配 | 实现 client.RemoteConnector，不向 GUI 暴露上游类型 |
| `third_party/teamspeak-go` | 固定版本上游快照与最小接收观察接口补丁 | 保留上游模块、MIT 许可与来源说明 |
| `internal` 中的配置存储包 | 书签加载和原子保存 | 不保存密码、身份密钥 |
| `internal/credentials` | macOS Keychain / Windows Credential Manager 中的服务器密码 | 实现 client.PasswordStore，不经 GUI 返回密码 |
| `internal/iconcache` | 有限内存与磁盘 PNG 缓存、过期与淘汰 | 不管理 TS3 会话或用户凭据 |
| `frontend/src` | GUI、视图状态和错误呈现 | 经集中 bridge 调用核心 |
| `frontend` 浏览器适配 | 前端开发预览 | 不声称真实 TS3 接入 |

M0 操作流：界面命令 -> Wails 绑定 -> Go 应用服务 -> 校验 / 存储 / 会话变更 -> Workspace 快照 -> 界面刷新。

所有修改操作返回更新后的快照，使服务端书签和会话状态有一个明确的权威来源。浏览器预览是单独适配器，数据不与桌面共享。

## 数据与会话

- `ServerProfile`：ID、显示名、地址、昵称、`skipPasswordStorage` 偏好。地址校验只代表输入有效，不代表服务器可达或协议兼容。
- `Workspace`：服务器书签、会话、频道、可见成员、消息、最近的通知事件。
- 会话模式：`offline`、`preview`、`connecting`、`connected`、`disconnecting`、`failed`。预览不会伪装成 `connected`。
- 预览仅当前频道包含本人；没有假远端用户、机器人回复或网络延迟。
- 预览消息只保存在进程内存。书签独立保存，退出预览不会删除书签。

连接有 30 秒超时；取消、断开和窗口退出由会话所有者回收资源。每次连接分配 generation，迟到事件不能改写新的会话。首次 `initserver`、`channellistfinished` 和本人所在频道信息到齐才完成连接；频道与成员通过同步观察接口按接收顺序归并。GUI 每秒读取快照，实时语音不经过此轮询。自动重连留待后续。

初始 ready 后适配器在独立任务中发送一次 `channelsubscribeall`，8 秒超时，使用连接生命周期取消。不能在同步协议观察回调中等待命令响应。`Session.memberSyncState` 区分 `pending`、`ready`、`limited`；拒绝或超时写入 `memberSyncError`，不令已建立会话掉线。订阅视图与状态更新不产生加入提示音。GUI 按频道展示同一份可见成员，订阅成功仍受服务器权限限制；不把缺少成员推送解释为确定的空频道。

服务器进入操作统一经过凭据准备与会话服务：双击或 Enter 使用已保存凭据直接连接，否则先打开密码框。`ConnectSavedServer` 与 `ConnectServerWithPassword` 在读取目标凭据、保存偏好之后才断开旧会话，再发起目标连接；准备失败保留原会话。目标地址在准备和实际连接间再次校验，不能把旧地址凭据送到被并发修改的新地址。不提供多会话或切换失败后自动回连。详见 ADR-0008。

本地提示音使用协议适配器产生的瞬时成员事件，应用服务保留最多 64 条带唯一 ID 的通知，随快照返回；短暂加入再离开不会因轮询漏掉。初始化和订阅视图更新静默，服务生命周期在实际转为已连接时产生一次连接成功通知，并负责自身断开通知。GUI 去重并忽略超过 5 秒的通知，通过 Web Audio 播放内置 WAV；成员提示与试听的同类提示间隔至少 400ms，真实连接和断开反馈按事件 ID 去重，不受试听或成员限频影响。连接成功音不受当前频道过滤，但必须仍属于当前已连接会话；异步资源加载后再次检查通知是否仍在当前队列，防止旧会话声音迟到播放。此队列只服务界面通知，不是持久消息总线。详见 ADR-0007。

`SelectChannel` 在远端会话中启动单个异步移动，8 秒超时，`switchingChannelID` 标记待定目标。`channelID` 始终由服务器事件更新。适配器同时等待命令成功响应与本人目标频道状态才完成操作；任意顺序均可。取消会清理本地命令等待与 tracker，不能撤回已发送的命令，所以迟到的真实状态仍要由当前会话处理。断开取消移动，旧会话结果不能影响新会话。密码频道根据 `channel_flag_password` 明确禁用。详见 ADR-0006。

## 频道消息与呈现

`ChannelMessageSender` 是连接的可选能力，客户端用 `SendChannelMessage(sessionID, channelID, text)` 绑定提交目标。应用层保留单条在途发送及 `sendingMessageID`，和本人频道移动互斥；后台结果用 generation 和操作序列隔离。协议适配器与频道移动共用命令门，并在上游节流之后、实际发包之前再次校验当前频道；整条命令的分片不能与其他命令交错。

TS3 的频道消息忽略 `target`，按照服务器处理时的本人频道投递。客户端串行化只能约束本地动作，无法消除管理员等外部强制移动与服务端处理之间的竞争。本轮不声称绝对指定频道投递或 exactly-once。命令响应成功只证明服务器接受；超时或发包后取消保守记为 `unconfirmed`，重试要求显式确认可能重复。

协议 `RemoteState.Messages` 只包含当前通知中的文字，应用层将其归并到本次连接合计最多 500 条的内存历史。瞬时消息必须在下一次状态更新时清空，不能由轮询重放。认证本人回显不新增消息行，本地发送行只由发送操作更新状态；其他用户的重复文本保留为独立消息。历史按频道浏览，断线后只读保留，开始新连接或预览时清空。草稿由 GUI 按服务器书签与频道保存在进程内，与历史生命周期分开。

`Channel.kind/align/repeat` 是归一化的展示语义。TS3 适配器仅把顶层永久且符合协议命名的频道识别为 spacer，去掉控制前缀并输出分隔项；GUI 不重新解析 TS3 原始名字。图标 ID 在适配器中归一化，已配置的自定义图标通过服务器文件传输下载，内置未映射图标与失败资源回退为标准图标。

图标下载只连接已建立 TS3 会话的同一 IP，不跟随下载通知提供的其他主机。每次 10 秒超时，输入最多 256 KiB、1024x1024 像素；单会话单 worker、最多请求 128 个不同图标，随连接取消。PNG/JPEG/GIF 验证解码后，使用 `golang.org/x/image/draw` 按比例缩小到不超过 256x256，不放大小图，再编码为最多 256 KiB 的静态 PNG。GUI 只接收有限大小的 data URL，不加载远端 SVG 或任意外链。详见 ADR-0009。

## 配置与错误

应用入口创建并注入图标存储，Connector 不再创建缓存。图标读取顺序保留内存 LRU、磁盘、网络；内存最多 128 项 / 8 MiB，磁盘最多 512 项 / 64 MiB，TTL 7 天，位于 `os.UserCacheDir()/resona/icons`。频道快照只保留 `iconRef`，协议状态也不持有图片正文。GUI 按会话及资源引用单独读取并缓存；引用按服务器、身份、端点和转换版本隔离，过期会话不能读取资源。GUI 解码和纹理占用独立于 Go 缓存预算，不把单层限额当成全进程内存。详见 ADR-0013。

配置存于 `os.UserConfigDir()/resona/servers.json`。目录权限 0700、文件权限 0600（以平台实际支持为准）；在同目录写临时文件，再原子重命名。不要在仓库中生成私人配置。

读取失败或 JSON 损坏必须返回错误，保留原文件，不能当作空配置覆盖。表单错误、存储错误、未来网络错误由 GUI 显示；操作失败时保留用户输入。

TS3 身份密钥保存为同目录 `identity.key`，权限 0600，完整临时文件通过不覆盖的原子链接发布；并发创建复用胜出的身份，损坏文件报错且保留。身份方案见 ADR-0005。

桌面服务器密码通过 `github.com/keybase/go-keychain v0.0.1` 调用 macOS 原生 Keychain，使用不云同步的 Generic Password 条目。凭据键为 `SHA-256(bookmarkID + NUL + address)`，值允许为空；是否存在通过独立查询判断。密码不进入 Workspace、书签 JSON、浏览器存储或日志。书签仅保存 `skipPasswordStorage`，其默认值 false 表示默认记住密码。其他平台或没有 cgo 时明确报告密码存储不可用，不退回明文文件。

只有认证成功且会话 generation、书签地址及偏好仍有效时才写入钥匙串。保存失败放入 `Session.credentialError`，保持已连接状态。修改名称或昵称复用条目，修改地址与删除书签清理原条目；独立忘记密码同时关闭该书签的记住偏好。凭据操作与连接生命周期分别串行化，具体存储接口与产品语义见 ADR-0008；该决定更新 ADR-0005 中早期只在连接内存中持有密码的范围。

## GUI 外观与视图状态

低资源常驻是桌面选型约束。Wails 当前作为可运行基线，下一步比较总进程成本与 Rust 原生 GUI 小样，不能仅凭宿主语言推断性能。候选、Go 核心复用边界及增量状态等待评估项见 [桌面 UI 评估](frontend-evaluation.md)；尚未决定替换 ADR-0002。

界面以紧凑服务器轨道、频道导航和聊天工作区组织内容，成员区域可收起；长频道列表与聊天历史独立滚动。默认使用石墨深色、低对比分区和少量冰蓝 / 薄荷色强调，毛玻璃限于导航、工具区和弹窗，正文保持清晰。浅色主题仍可选择。设计参考 Oopz 的信息密度与层级，不复制其品牌或素材。

主题偏好采用新的版本键以启用本轮深色默认值，之后持久保存用户选择；书签、凭据与声音偏好不随外观迁移重置。颜色和材质来自共享 CSS tokens；不支持 backdrop-filter 时保留可读的实色背景。视图收起不改变服务端会话、成员订阅或消息目标。

## 协议与音频边界

TS3 协议适配负责身份握手、可靠命令、事件与语音包。客户端应用层负责用户操作和会话状态；GUI 不依赖第三方库的类型。

本轮 `internal/audio` 已实现采集、Opus 编解码、有界队列、抖动缓冲与混音，malgo 提供平台设备路径。GUI 只传配置和状态，不经 JSON 桥逐帧搬运 PCM。Go 服务用连接代数、语音 epoch 与操作序列隔离取消和迟到结果。实际设备、TS3 网络及官方客户端互通是独立验收项，状态见 verification.md，详见 ADR-0012。

先围绕真实需求形成最小接口，不提前设计一个包含所有未来协议的庞大通用 Client 接口。频道、权限和错误语义必须以已验证的 TS3 行为为依据。

## 未来扩展与服务端

本期原生交互补充见 ADR-0014：连接成功后自动仅收听；本地麦克风试听与网络发送互斥；激活模式不解除静音；音频处理采用固定版本 SpeexDSP。正常退出先关采集并等待连接清理，再按设置完成本地断开提示音；清理和播放均有限时，Rust 保留最终进程回收。频道和用户详情只在选中时异步读取，按会话、目标和实体版本隔离，服务器未提供的字段不推断成空值或无限容量。

内置扩展使用事件与命令接口，核心统一持有连接、身份、发送队列与音频设备。外部插件边界另见 ADR-0004。

客户端与服务端可以共享协议编解码和确实一致的值类型，但不共用一个含混的全局状态模型。服务端是会话、频道和权限的权威方；客户端是远端状态的观察者。

服务端仍在同仓库演进，是否拆 Go module 或仓库取决于独立发布和外部引用需求，而不是目录数量。

## 单成员本地收听

麦克风输入增益独立于收听增益，通过`VoiceConfig.inputGain`与`SetInputGain`控制；设置及两种试听共用采集处理段。Service隔离生命周期切换，Engine无等待取得控制令牌后发布原子配置快照，不重建设备。VAD读取增益前电平，编码和本地试听读取增益并限幅后的PCM；正常语音不增加逐帧IPC。原生偏好保存已确认的增益，参见ADR-0014。

`SetUserPlayback` IPC 以会话ID、成员ID和成员实例令牌定位目标。Service验证当前频道与范围，保存连接内偏好；TS3适配器为成员进入分配实例并给内部音频包标记实例。混音器原子读取不可变参数表，在每个发送者的PCM叠加前应用独立增益，再沿用总音量与限幅。静音仍消费该成员的抖动缓冲，解除时不回放积压内容；GUI只传控制参数，不传PCM、不发TS3静音命令。详见ADR-0017。

## 验证策略

- Go：配置保存/重载、非法输入、损坏配置保护、会话命令边界。
- 前端：书签新增编辑删除、预览进出、频道选择、消息、表单和错误状态。
- 桌面：macOS 构建、窗口启动、桥接与真实配置保存。
- 协议：独立真实服务器集成测试，记录双方版本，不能用本地预览替代。

# ADR-0029：本地配置升级与发布入口

- 状态：Accepted（配置保护与本地更新流程）；Pending（公开发布配置与 Windows 验收）
- 日期：2026-10-14

## 配置

应用版本、配置格式版本和网络/IPC 协议版本各自独立。配置增加整数
`schema_version: 1`，不使用应用版本字符串推断迁移。

桌面 `native-preferences.json` 保持对象格式，Go `servers.json` 从数组迁移为
`{"schema_version":1,"servers":[...]}`。无版本旧配置只在内存迁移；读取不改文件。
首次保存先将原始字节备份到同目录的 `<原文件名>.pre-v1.bak`，再写临时文件、
同步并 rename 替换。备份为用户私有文件，永久保留一份，不定时写入或自动删除。
已有备份只有与原始字节一致时可复用；冲突或备份失败中止保存。

缺文件使用正常首次安装默认值。桌面读取失败使用独立恢复配置：自动开麦关闭、
3A 全关；显示持续提示。本次设置仍可应用，但设置、快捷控制和退出都不保存。
用户从诊断页在文件管理器中定位配置目录，手动修复后重启；不热重载配置或自动重置原文件。
书签读取失败继续阻止 Core 启动，不把损坏书签当空列表。

每次保存检查现存文件，拒绝损坏、超限、未知版本及 v1 未知字段；单文件读取
和写入上限 1 MiB。桌面校验包括处理链及参数，书签沿用严格字段和 ID 校验。
桌面异步保存按修订序号串行，旧任务不覆盖已保存的新修订。
这不提供跨进程事务：不支持多个实例或外部编辑器在保存期间同时修改配置。
保护保证针对本进程读取时观察到的异常，不宣称无锁检查能抵御外部替换竞态。

已应用但落盘失败须明确“本次有效，未保存”，不能先显示“已保存”。启动或
保存异常后维持保护提示，修复后重启。发布前没有版本保护的旧二进制不能获得
此保证；二进制回滚不等于配置降级，不自动恢复迁移备份。

## 更新流程

用户选择保留 Windows 便携 ZIP：应用内下载，退出后替换整个安装目录中的产品
文件，保证 Desktop、Core 与 WebRTC 原生库来自同一发布。配置继续位于用户配置
目录，不随 ZIP 解压覆盖。

关于页提供手动检查、下载、取消和 Windows 退出更新。独立有界 worker 校验
Ed25519 清单、版本、HTTPS 地址、SHA-256、字节数和 ZIP 产品标记。安装器由
当前可信 Core 复制，使用独立目录，ready/commit/armed 交接后才退出应用；
准备失败保持应用运行。整目录替换失败回退，启动新版进程失败回退并启动旧版。
保留 `.previous`，不宣称覆盖断电或新版运行期崩溃；详情见 ../updates.md。

更新源通过构建变量配置。私有源码仓库需要另行提供公开发布仓库或下载服务；
源码仓库公开时可以直接使用其 Releases。仓库选择尚待确认，不更改可见性。
签名公钥、发布凭据和公共清单尚待配置；临时 Actions artifacts 不作为更新入口。
发布标签和已发布版本的包不可移动或替换。Windows 原生验收尚未完成。
macOS 公共分发需独立完成 Developer ID 与 notarization，现有开发签名不能冒充
完整公开分发流程；本期 macOS 只下载校验，不自动安装。
更新下载/安装不得加入语音热路径或空闲高频计时器。

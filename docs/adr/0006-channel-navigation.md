# ADR-0006：频道切换以服务器状态为准

- 日期：2026-09-07
- 状态：Accepted
- 扩展 ADR-0005 的只读边界，仅开放本人无密码频道移动。

## 决定

GUI 复用 `SelectChannel(id)`，应用服务只接受已知的无密码频道。操作立即返回带 `switchingChannelID` 的快照；单会话只有一个移动，超时 8 秒。适配器构造 `clientmove` 的本人 ID，GUI 不能传入其他用户 ID。

实际 `channelID` 只由服务器通知更新，不进行乐观切换。适配器等待命令成功响应和自身目标频道状态，两者到齐才完成；权限失败保留真实频道并展示中文错误。命令等待取消不能撤回网络上已发送的命令；超时后的迟到状态仍须如实显示。

断开与退出取消移动并等待清理，generation 和操作序号隔离迟到结果。频道列表以 `channel_flag_password` 维护密码标记；当前没有频道密码输入和验证能力，因此明确禁用此类入口。

## 上游补丁

增加 `ExecCommandContext(ctx, cmd)`，将节流和响应等待放入同一个 context，复用原命令实现；原 duration API 保留 timeout sentinel，但时间预算也覆盖节流。tracker 在取消和完成时删除 pending/collecting，重复及迟到完成响应不能阻塞接收循环。没有解决所有无关联数据行的并发查询问题，因此应用操作仍串行。

服务端错误提供可 `errors.As` 的 `CommandError`，适配器只读取数字 ID，并把权限不足、频道密码错误映射为稳定的应用错误；不将原始服务器文本或命令暴露给界面。错误编号依据 [官方错误枚举](https://github.com/teamspeak/ts3client-pluginsdk/blob/master/include/teamspeak/public_errors.h)。

## 验证与边界

本地覆盖 ack/事件两种顺序、权限拒绝、密码限制、无乐观变更、断开取消、超时和旧会话隔离。前端 mock bridge 覆盖失败与迟到 UI 响应。真实服务器只创建一个临时专用测试频道，使用获授权的持久身份进入该频道，核对本人状态后断开；夹具退出后被动核对该频道已删除。

不发送文字或音频，不进入既有业务频道，不修改服务器权限。当前权限已允许这次临时频道创建；后续出现明确权限拒绝时仍需等待用户授予所需权限。完整权限矩阵、密码频道与原生窗口完整点击流程仍待验证。

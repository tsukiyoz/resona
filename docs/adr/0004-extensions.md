# ADR-0004：内置扩展先行，外部插件契约延后稳定

- 日期：2026-09-07
- 状态：Accepted

## 背景

长期希望支持音乐、自动化与无界面机器人，但当前会话和音频接口尚未经过真实使用验证。

## 决定

先用编译进应用的内置扩展检验生命周期、事件、命令和能力接口。GUI 与无界面机器人复用 Go 核心，不把机器人业务写进 UI。

核心统一管理连接、身份密钥和音频设备；扩展只能经明确能力接口操作。音乐扩展优先，第三方动态加载、进程协议和公开 SDK 不进入 M0。

外部扩展引入时优先评估独立进程隔离与版本化 RPC，具体传输和权限策略另立 ADR，不提前承诺接口。

## 代价

首批扩展修改需要重新构建应用，暂不支持第三方直接安装。可以避免过早稳定一个未经验证的通用插件 API。

## 重新评估条件

音乐和至少一个自动化扩展形成共同需求，或用户需要独立安装第三方扩展时，制定 SDK、生命周期、能力授权和错误隔离方案。

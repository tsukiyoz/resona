# ADR-0031: 有界频道历史与嵌入式 JetStream

状态：Accepted，2026-10-21。取代产品中“文字仅实时广播、离开后不恢复”的约定。

ADR-0033 将同一个 broker/数据目录扩展为管理资源 KV；聊天流和 KV 桶分别限制，
聊天淘汰不影响频道或 owner。

## 决策

频道文字保留有限近期历史，服务器重启后仍可恢复。用户确认默认每频道 200 条、
全服聊天流 64 MiB、最长 7 天，任一限制达到按消息顺序淘汰最旧数据。
CLI 可调整限制。64 MiB 是流中保留消息的逻辑大小，不是目录的严格磁盘配额；
索引、元数据、块文件和回收过程另有占用。流上限与 broker 自动磁盘预算分离，
重启时先恢复旧流再应用新上限，避免调小限制时因旧数据超过新预算而恢复失败。
历史是尽力保留，不是永久归档。

使用嵌入式 nats-server JetStream FileStorage / LimitsPolicy / DiscardOld，
一个流、每频道一个 subject，MaxMsgsPerSubject 限制每频道条数。
DontListen + nats.go InProcessServer 使用进程内连接，无客户端 NATS 依赖、
独立服务或额外公开端口。没有集群、永久用户游标、已读回执或搜索。

依赖为 nats-server/v2 v2.15.1（发布提交 b2fd3ef）和 nats.go v1.53.1，
以 go.sum 校验模块；集成核验了这两个版本的 server.Options、InProcessServer、
CreateOrUpdateStream、CreateConsumer 和 Messages 实际 API，并运行本地集成测试。
不能仅由 NATS 的吞吐宣传推断 Resona 变快；相对直接广播增加文件存储、后台任务、
内存和依赖，选择它是为了复用有界保留、顺序和恢复，而非优化语音热路径。

## 提交与接收

服务端从已认证连接取作者身份、频道和昵称。客户端提供消息 ID，服务端按
身份 + 频道 + ID 去重，窗口为 min(2 分钟, MaxAge)。聊天发布在共享成员锁外执行，
使用 2 秒期限；JetStream 启用 SyncAlways，成功发布确认后才回复业务成功。
明确存储拒绝与结果未知区分；结果未知不自动重发，用户确认重试可能在去重窗口外
产生重复。语音不等待聊天文件 I/O。

2026-10-23 增补：首次进入只读取最新最多 20 条/48 KiB。查询前记录该 subject 的
高水位，临时 pull consumer 从高水位+1 开始；查询期间发布的消息仍由 JetStream
保留并交给 consumer，避免历史与实时的交接间隙。每个成员仍只有一个实时 consumer。
向上翻页使用 before 排他游标，同 subject 的上一条由 v2.15.1 实际 direct multi_last /
up_to_seq API 解析，单页至多 20 条及一次前瞻，不按全局序号减 20、扫描全部历史、
另建正文缓存或永久用户游标。AllowDirect 仅对不监听外部端口的内部 broker 开启，
既有流在打开时补齐该标志，不修改其保留配置。实际集成测试覆盖序号空洞、
重启、字节/条数上限、过期空页与查询期间并发发布。

流序号与原始存储时间稳定；本人
判定使用持久身份，不用会被复用的临时成员 ID。消息带客户端 ID 以合并本人回声，
带频道 epoch 拒绝迟到的旧频道数据。历史不会增加未读提示。

换频道、重新加载或退出取消旧 consumer；临时消费者主动删除，并有 30 秒空闲回收。
拉取批次最多 4 条 / 48 KiB，聊天单独使用 4 槽发送队列，复用原写循环并优先处理
控制消息，不能填满关键控制队列；不新增写线程。客户端显示缓存仍为 500 条 / 512 KiB，启动期间的
消息增量也有同样边界。实时超预算淘汰最旧显示记录；旧页超预算停止翻页并提示，
不加载后立即淘汰同一页，避免反复请求。独立 ChatPage 响应核对 request、频道 epoch、
订阅 generation 及原 before；翻页不重建实时 consumer、不进入全局同步状态。
首次连接与重连必须保留 admission 之前收到的消息增量。

加载、可用、失败通过独立 ChatStatus 通知。失败显示手动重试，保留语音与退出；
聊天和资源回复超时不关闭健康传输，但控制写入失败仍作为连接故障处理。
IPC 重试异步且有界，不阻塞主循环。没有客户端历史轮询。

2026-10-23 呈现补充：首批历史在现有会话有界缓存内积累，ChatStatus 就绪后
一次投影到工作区；加载中不逐条发布消息展示更新，其他状态事件也不能泄露部分
历史。实时消息和向上翻页保留原语义，不增加第二份历史缓存。前台加载超过
300ms 才显示提示，失败立即可见；一次性延迟任务随范围/状态及前后台变化取消。
这是展示与通知合并，不阻塞 GUI、控制接收或音频，也不要求聊天先于连麦就绪。

## 运维与验证

产品默认把数据写在 access-dir/chat，随现有数据卷保存；需备份完整权限/聊天目录。
存储明文聊天，权限目录应仅服务端账号可读；Noise 只是逐跳加密。聊天正文不写日志。
库级未指定 Directory 时使用临时目录，仅供测试/嵌入调用，不承诺跨进程保留。
实验握手升级为 RN06，客户端与服务器同步更新，不能对 RN05 做无提示降级。

本地测试覆盖条数/全局字节/年龄淘汰、重启恢复、历史到实时连续顺序、去重、
频道隔离、稳定本人身份、消费者取消、首次/重连 setup 消息保留、超时保留语音与
IPC 退出。Windows 实机、长期磁盘占用与等负载服务端性能仍需独立验收。

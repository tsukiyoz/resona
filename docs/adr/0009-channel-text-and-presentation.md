# ADR-0009：协议适配边界、频道文字与真实频道呈现

- 日期：2026-09-07
- 状态：Accepted
- 扩展：ADR-0003 的 TS3 首个兼容目标与 ADR-0006 的频道操作边界。

## 方向

Resona 的长期目标是自有客户端、服务端和 Go 生态。TS3 是第一个协议适配器，当前优先验证普通 TS3 服务器上的客户端体验；未来服务端也需要用官方客户端和 Resona 客户端分别验证兼容范围。可能增加自研协议，但需要功能缺口、端到端延迟、可靠性或维护成本等测量依据，不提前构造空的第二套协议。

Go 客户端核心负责用户操作、会话、消息状态和展示模型，协议适配器负责线上命令、事件和协议专有资源。未来服务端拥有自己的权威状态，不复用客户端服务作为服务器。只共享语义确实一致并经过互通验证的值类型与协议组件。

## 频道纯文本

本轮仅实现已加入频道的纯文本。`ChannelMessageSender` 是连接的可选能力，不引入私聊、广播、富文本、附件、编辑撤回或已读。发送参数绑定会话 ID 与频道 ID，校验有效 UTF-8、非空、无 NUL 和最多 8192 字节；服务端可能有更小限制。正文作为文本渲染。

应用服务只允许一条在途消息，用 `sendingMessageID`、generation 和操作序列处理完成、取消与迟到结果。发送与本人切频道在应用层互斥，在 TS3 适配层共用命令门；上游节流之后再次检查频道，再串行发出完整命令分片。断开仍能取消等待，不必等到发送超时。

TS3 的频道消息不按 `target` 原子指定目标，而使用服务器处理时的本人频道。本地门和发送前校验可以避免本客户端主动切换造成的误投，却无法消除管理员等外部强制移动与服务端处理的竞态。不能宣称绝对指定频道发送或 exactly-once。

状态为 `sending`、`sent`、`failed`、`unconfirmed`，收到的消息为 `received`。`sent` 只表示服务器接受；明确拒绝或确认未发出是 `failed`；无法确定结果时为 `unconfirmed`。不自动重试；未确认消息必须显式确认可能重复后才能重试，且仅允许在原连接原频道操作。

本地发送行由发送操作持有，认证本人的协议回显不新增消息行，避免重复显示；不同发送操作即使正文相同也保留为两条。接收事件为本次协议回调的瞬时数据，不由后续快照重放。历史跨频道合计最多 500 条，仅属于本次连接；断开后可只读查看，开始新连接或预览时清空，不保存到磁盘。

GUI 草稿按服务器书签和频道保存在当前进程，与历史分开。发送中暂禁输入，本人切频道或掉线不丢草稿；只有成功结果清理原提交草稿，迟到结果不能清理新会话内容。浏览历史时收到消息不抢滚动。

## Spacer 与图标

TS3 适配器仅将顶层永久且符合 spacer 命名规则的频道归一化为 `kind=separator`，输出剥离控制前缀后的名字及对齐、重复语义。GUI 将其显示为空白或标题分隔，不提供加入动作；普通频道保持原名。TS 专有名字解析不散落在聊天或通用导航代码中。

频道自定义图标使用服务端配置的实际资源，通过 TS 文件传输下载。内置 ID 未映射、无资源或失败时使用标准频道图标，不猜测或复制官方素材。图标占位尺寸固定，锁及当前频道状态与图像独立。

每个图标输入最多 256 KiB、1024x1024 像素、10 秒超时；单会话单 worker 且最多请求 128 个不同 ID。只连接当前 TS 会话已确认的服务器 IP，连接退出取消下载。PNG/JPEG/GIF 解码后，使用 `golang.org/x/image v0.41.0` 的 CatmullRom 按比例缩小到不超过 256x256，保留透明度且不放大小图；输出静态 PNG 仍最多 256 KiB。GUI 接收有限大小的 data URL，不跟随任意外部 URL 或直接渲染远端 SVG。这个输入与输出分离的限制来自真实服务器上存在超过 256 像素图标的验证结果。

## 验证

本地测试覆盖状态与权限、取消、迟到事件、成员更新不重放消息、长度与转义、图标资源边界和 spacer 识别；前端验收覆盖草稿、重试、离线记录、滚动与资源回退。通过这些测试不能替代真实双端消息互通或桌面验收。

真实测试仅在 Resona 自建专用频道内进行，不进入既有业务频道或操作他人。单元、前端回归与专用频道的实际文字往返已通过，具体结果和剩余验收记录在 `docs/verification.md`；上一版 `268b528` 的用户验收不等于本轮桌面验收。

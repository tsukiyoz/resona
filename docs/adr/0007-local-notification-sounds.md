# ADR-0007：协议事件驱动的本地提示音

- 日期：2026-09-07
- 状态：Accepted

## 决定

本人成功连接服务器、断开连接，以及当前频道成员加入、离开，在本机播放四种短音调。提示音属于 GUI 输出，不经过 TS3 音频发送、不采集麦克风，不依赖将来的语音编解码流水线。

协议 reducer 按接收顺序产生 `RemoteEvent`，每次回调只含本次变化。应用服务在已连接状态下过滤本人和其他频道事件，将 `Notification` 保存在最多 64 条的内存队列中，包含唯一 ID、类型、频道与时间。GUI 每秒轮询已有 Workspace 即可拿到短暂进出的两个事件，不通过成员快照差分推断。

本人连接成功和断开由会话生命周期产生。连接完成且 generation 有效、实际转为 `connected` 时产生一次 `connected` 通知；重复同步不产生成功通知。主动断开与服务器关闭均只通知一次；关闭整个应用和未成功连接时的取消静默。普通断开后保留队列，下一次连接或进入预览时清空。队列不持久化，不承诺无限积压或完整事件审计。

GUI 首次读取只标记已有事件，后续按 ID 去重，超过 5 秒不播放；成员提示与试听的同类提示最短间隔 400ms，成员通知仅适用于仍在当前频道的已连接会话。真实连接和断开反馈按独立事件 ID 等待资源，不受试听占用或 400ms 限频影响，避免刚试听后连接成功却无反馈。连接成功通知只检查已连接状态与当前队列，不受频道变化影响；声音加载后重新检查，旧会话通知或已断开的成功通知不能迟到播放。连接按钮或试听操作中的用户手势解锁 Web Audio。设置保存总开关和音量，默认启用、35%；关闭立即停止输出并消费事件，重新开启不补播。

四份 PCM WAV 是仓库脚本 `frontend/scripts/generate-notification-sounds.mjs` 确定性生成的原创音调，没有复制官方音效。文件随桌面前端资源打包，不需要外部媒体请求。将来音效包或语音提示基于实际需求再扩展。

## 协议边界

官方 [原因枚举](https://github.com/teamspeak/ts3client-pluginsdk/blob/master/include/teamspeak/public_definitions.h) 将 `reasonid=2` 定义为订阅变化，必须更新成员但保持静默。缺失、未知及频道编辑原因也不提示。初始通知没有完整成员列表结束标记，`channellistfinished` 只结束频道列表；参考 [协议研究](https://github.com/ReSpeak/tsdeclarations/blob/master/ts3protocol.md)。

因此不以延时猜测初始化结束，而是在已有本人频道和初始频道列表后，仅处理明确成员变动原因，排除订阅快照、本人移动和重复通知。依赖服务器按约定标记订阅原因，不能保证非标准服务器行为。上游拆行补丁为批量成员通知继承首行共享频道和原因字段，保留每行覆盖，不继承成员身份或昵称。

## 验证边界

分别验证协议通知归并、应用服务生命周期与队列、GUI 去重和 Web Audio 实际资源解码。浏览器注入 bridge 的事件测试不替代真实 TS3 集成验收。真实人员进出验证只在 Resona 自建专用频道进行；此次功能开发不需要创建服务器资源。

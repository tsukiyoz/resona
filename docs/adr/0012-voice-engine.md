# ADR-0012: Go 实时语音路径与显式设备生命周期

- 日期：2026-09-08
- 状态：Accepted
- 关联：ADR-0003、ADR-0011

## 决定

`internal/audio` 持有设备、编码解码、有限队列和混音。TS3 适配实现语音包观察、发送、频道 codec 与服务端静音状态更新；应用服务持有 Engine，将其生命周期绑定当前连接。GUI 不处理 PCM 或 Opus 帧。

设备通过 `github.com/gen2brain/malgo v0.11.26` 的 miniaudio 后端接入，目标为 macOS CoreAudio 与 Windows WASAPI。Opus 使用 `github.com/thesyncim/gopus v0.1.1`，固定源码 commit `c0d8ecac85f5fe7fd45b5d76fd5c3ada0f26ebfa`；该纯 Go 实现的上游差分测试与实际链路验证须分别记录，不能仅引用其 README 声称兼容。

首轮支持 TS3 Opus Voice（4）和 Opus Music（5）。不支持的频道 codec 返回明确错误；不静默用错误编码发送。协议加密依据服务器与当前频道状态处理，缺少必要状态时拒绝发送。

只有真实连接允许启用语音。首次启用保持麦克风静音，仅打开输出；用户明确取消静音后才打开输入设备。耳聋禁止采集、发送和播放，保留原麦克风静音偏好。停用、断开、退出取消在途启动并释放设备和缓冲，旧 Engine 关闭完成后才允许替代者安装传输回调。

会话 generation、voice epoch 和操作序列隔离迟到结果；频道变化重置音频路径，避免旧频道缓存播放到新频道。设备失败只影响语音，文字连接继续，错误通过 voice 状态显示。首次不自动重试打开麦克风。

本地四类提示音复用内置 WAV，经独立可取消播放器输出，不发送到 TS3。提示音开关、事件去重与过期仍由 GUI 控制；耳聋时停止提示音。

验收后补充语音活动指示：音频引擎根据解码后、输出缩放前的有声 PCM 和成功发送的本地有声 PCM 更新活动状态，约 300ms 无新有声帧后释放。只在状态变化时通知；GUI 接收成员 ID 集合与自身状态，不接收逐帧音量。应用层过滤非当前频道成员，配置、断开与旧实例隔离规则同语音生命周期。此检测只驱动指示灯，不实现 VAD 发送门控或人声识别。

结束发言与坏帧必须分别处理。TS3 空音频结束标记参照 [协议研究的 Voice 章节](https://github.com/ReSpeak/tsdeclarations/blob/master/ts3protocol.md) 与 [TSLib 接收实现](https://github.com/Splamy/TS3AudioBot/blob/master/TSLib/Audio/AudioPacketReader.cs)；带完整说话者头部且无音频的包结束对应流，不交给 Opus 解码。非空音频仍须按 Opus 格式判断，不能把所有单字节音频一律丢弃。孤立坏帧不应留下永久设备错误，持续解码异常必须保留可见诊断；恢复只能清除对应解码错误，不能掩盖设备或发送故障。

## 范围与限制

本轮不含按键发言、语音激活、回声消除、降噪、录音、音乐机器人或官方客户端完整功能对等。避免扬声器回声的日常使用建议耳机；不可把基础通话实现描述为完成电竞级音频调优。

验证分为纯算法与并发生命周期、真实服务器双向 Opus 转发、本机设备回调与启停、GUI 麦克风授权，以及官方客户端交叉听测。各项结果独立列出；Windows 运行与长期游戏负载测试仍需目标机器。

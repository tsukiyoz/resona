# ADR-0008：成员可见范围、服务器进入与系统钥匙串凭据

- 日期：2026-09-07
- 状态：Accepted
- 密码仅通过系统凭据存储保留；持久身份与密码生命周期独立。

## 背景

用户验收发现成员不够可见、长频道列表无法完整浏览、每次连接都需输入密码。客户端需要把服务器进入、频道浏览、成员同步和失败恢复连成可重复使用的流程，同时如实呈现当前身份的权限范围。

## 决定

### 成员与频道浏览

频道树保留服务器推送的频道层级和顺序，并在每个频道下展示已经同步的可见成员，标记本人。树和当前频道详情使用同一份 Workspace 状态。侧栏允许长列表滚动，自动定位仅随新会话或本人切频道发生，不因轮询和他人进出重置滚动位置。

初始连接 ready 后异步发送一次 `channelsubscribeall`，8 秒超时，并随连接结束取消。协议观察回调不等待请求结果。成员同步状态为 `pending`、`ready`、`limited`，分别代表请求中、命令成功、超时或拒绝。失败保留已收到的成员和已建立会话，另行报告原因；成功仍只表示服务器授予当前身份的可见范围，不能宣称全服务器用户完整可见。订阅快照与状态更新保持提示音静默。

### 进入与切换服务器

单击选择服务器，双击或聚焦后 Enter 执行进入。已记住凭据时直接连接，包括已保存的空密码；没有凭据时打开密码框。已连接或正在连接的同一服务器不重复发起会话。

切换另一服务器先准备目标凭据和偏好，再断开旧会话并建立新会话。关闭密码框、凭据读取失败或准备阶段存储失败不改变原会话。新连接失败后显示失败，不自动连接回旧服务器。继续保持单一会话，不引入多服务器并行连接。

### 凭据保存

Go 核心依赖 `client.PasswordStore`，macOS 适配由 `internal/credentials` 使用 `github.com/keybase/go-keychain v0.0.1` 调用原生 Keychain。Generic Password 条目不启用云同步。2026-09-10 加入 Windows Credential Manager：通过已有 `x/sys/windows` 调用 CredReadW / CredWriteW / CredDeleteW，使用当前用户的 Generic 条目及 LOCAL_MACHINE 持久级别（跨登录保存，非所有用户共享）。目标以 `io.github.tsukiyoz.resona.server-password/` 隔离，blob 为版本化 JSON，支持空密码，读取后释放系统内存。不要求 cgo；其他平台及 macOS 禁用 cgo 的构建报告存储不可用，不退回明文文件。

凭据键为 `SHA-256(bookmarkID + NUL + address)`。键绑定书签及目标地址，不能因书签改名而丢失密码，也不能将旧密码发送给新地址。独立的存在性查询区分未保存与已保存空密码。GUI 只接收保存状态，不读取或回填已保存密码值。

2026-09-10 授权体验修订：macOS存在性查询明确设置 `kSecUseAuthenticationUIFail`，只请求属性且禁止认证UI。若系统返回 `errSecInteractionNotAllowed`，将其视作需要显式读取的候选条目；这不是已成功读取密码的证明。随后仅 `Get` 允许交互认证；缺失、拒绝或读取失败走原有手动输入路径，不自动重试、不先断开旧会话、不缓存明文来绕过授权。原查询虽然已不返回秘密数据，但仍缺少非交互约束；本轮测试验证查询策略及原生API兼容，不宣称重现了用户原有条目的两次系统弹窗。核心目前为ad-hoc签名，更新二进制仍可能触发新的访问确认，稳定签名发布另行处理。

2026-09-14 修订：用户再次报告重复授权，成功读取/保存的凭据现在按原目标键缓存在 core 的 Store 实例内，覆盖以上“不缓存”约定。并发读取由 Store mutex 合并；相同已缓存值不重复写回，更新/删除尝试先失效，失败结果不缓存。缓存随进程退出消失，外部钥匙串编辑需重启读取，不代表系统授权被持久化。不同旧条目的首次读取仍由系统 ACL 决定，不启动批量读取。签名检查确认当前 core 为 linker ad-hoc，identifier 为 a.out；跨版本持久授权不能据此保证。

传统 file-based macOS Keychain 的状态查询同时用 `SecKeychainSetUserInteractionAllowed(false)` 约束，并恢复先前值。该兼容 API 已 deprecated，但对应本项目现有传统钥匙串；不迁移或放宽条目 ACL。由于设置是进程范围，所有此适配器的原生查询/写入/删除共享互斥，防止静默状态查询抑制显式授权。现有 `kSecUseAuthenticationUIFail` 仍保留。此为防御修复，不宣称已复现用户现有条目的两次系统弹窗。

钥匙串条目内部采用版本化 JSON 保存密码，保证空密码也写入非空数据；原生测试发现直接用零字节数据更新时可能保留旧值。读取严格检查格式和版本，不提供明文文件回退。

2026-09-16：显式读取现有传统钥匙串条目改用一次 `SecKeychainFindGenericPassword`，按 service/account 精确查找；返回内存由 `SecKeychainItemFreeContent` 释放，解析后清理 Go 临时字节。保留静默存在性查询、进程内成功缓存及拒绝后不自动重试。此 API 与现有传统存储匹配，但已被 Apple 弃用，后续稳定签名及存储迁移需单独评估。库原来的 `SecItemCopyMatching` 也只有一次显式调用，因此不能将此次调整描述为已证实消除了两次调用；用户原条目的连续双提示尚待复测。系统解锁与条目授权仍由 macOS 控制，不放宽 ACL。

记住密码默认启用，`skipPasswordStorage` 作为非敏感偏好保存在书签 JSON。仅认证成功且当前 generation、地址及偏好仍有效时写入凭据，失败认证不覆盖原密码。修改名称或昵称保留凭据，更改地址和删除书签清除原条目。独立“忘记已保存密码”操作删除条目并关闭该书签的记住偏好。

凭据保存失败使用 `Session.credentialError` 显示，不把已建立会话改为失败。连接失败页面保留“修改密码”入口，避免只能不断重试失效凭据。密码值不进入 Workspace、书签文件、浏览器存储或日志。

## 验证边界

2026-09-16 后续反馈：用户在新包首次连接时点击“允许”，仍连续出现两次相同条目授权，说明直接读取调整未解决该问题。加入每次原生操作的开始/结束、关联序号、耗时及 OSStatus 到现有有界内存诊断；不记录条目键、密码或原生错误描述，不新增文件写入或空闲定时器。下一步依据实际复现导出的调用边界判断重复发生在系统调用内部还是不同操作之间，不能仅凭调用次数测试宣布修复。

同日实机根因确认：诊断中仅有一次静默状态查询（11ms）和一次显式读取（4455ms），无写回；对应系统 securityd 日志先显示旧条目 ACL 的访问提示，用户允许后记录 `ACL partition mismatch`，随后 `asking user about XARA partition` 并再次提示。现有条目保留旧构建的 cdhash，而当前 core 为 linker ad-hoc 签名，构建改变 cdhash 后授权身份不连续。应通过稳定的受支持签名身份解决跨构建识别，而不是继续更换读取 API、自动重试或放宽条目 ACL。当前机器没有可用代码签名身份；稳定签名及旧条目首次迁移授权仍待完成，不能保证“始终允许”跨 ad-hoc 构建有效。

本地测试覆盖空密码与非空密码、认证失败不覆盖、保存失败不掉线、地址变更清理、单一会话切换、成员订阅状态、长列表滚动和键盘进入。Go race 与前端回归不等同于原生 Keychain 或真实服务器验收。

原生凭据需要验证创建、查询、更新、删除和进程重启后读取。真实成员验证只能在 Resona 自建专用测试频道进行；不能为补齐视图而修改服务器权限或操作他人。具体已完成证据记录在 `docs/verification.md`，本 ADR 不提前宣称这些验证通过。

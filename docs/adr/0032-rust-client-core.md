# ADR-0032: 逐步迁移至进程内 Rust 客户端核心

状态：Accepted，2026-10-21；迁移进行中，尚未替换产品核心。

## 决策与范围

客户端目标为 GPUI + UI 无关的 Rust library，通过有界命令/事件通道交互，
不再启动 Go 子进程或使用桌面 NDJSON IPC。Go 服务端保留，JetStream 继续内嵌；
生产入口显式把聊天目录设为 access-dir/chat，不依赖 NATS 的临时目录默认值。
库级未指定目录的临时存储仍只用于测试/嵌入场景，见 ADR-0031。

移除双语言状态映射、子进程启动/关闭和打包配套是本次确定的维护目标。
现有音频不经过桌面 IPC；不能把迁移描述为消除了逐帧 PCM 跨进程传输。
常驻内存、CPU、唤醒和游戏干扰是否改善，须在最终相同负载下计入全部进程测量。
Rust 核心可继续调用成熟的 Opus、SpeexDSP、WebRTC、RNNoise 原生实现；
不因迁移重新实现算法、不改变已保存处理链、不接入客户端 NATS。

## 分步替换

1. client/ 建立独立 Rust crate，实现 RN06 传输和共享 Protobuf/身份证明，
   对现有 Go 实现做实际回环互通。没有 GUI、设备、持久身份或生产路径切换。
2. 迁移认证会话、命令/事件、资源/聊天、重连及配置/凭据/诊断/更新行为，
   保留状态代次、取消和失败分类。现有身份 seed 与配置须直接继承，不重置用户。
3. 迁移设备、Opus、抖动/混音、3A、PTT 与提示音，验证回调无阻塞，处理器
   在帧边界替换且由所属 worker 销毁。复用已有听音样本和 benchmark。
4. 覆盖完整产品验收后，将 GPUI 接入 Rust 通道，再删除 Go 客户端专属代码、
   桌面 IPC 和旧打包路径。共享服务端传输/协议不能误删。没有永久双核心选择器。

每步可独立验证；主产品在替代功能完成前继续使用已验证的 Go Core。
新 Rust 网络基础不等于全 Rust 产品完成，不发布模拟连接/语音或静默缺失功能。
保持现有 RN06、prologue、二进制字段与身份证明；语言迁移本身不升级应用协议。

## 传输实现约束

首步使用 snow 0.10.0（发布源码提交 4bb43f50370bdb3e8b1b57814ac662864db2704f；
确切包校验和及依赖见 client/Cargo.lock）。集成查验了
该发布源码的 Builder、HandshakeState、DefaultResolver 和 Cipher API，并核对
握手完成后的 raw split、显式 nonce、带 AD 的 AEAD 及 Noise Rekey 调用。
高层 TransportState 不支持 Resona 的 5 字节头 AD，因此仅在完整 NK 成功后取出
方向密钥；临时密钥副本清零，所有发送 nonce、接收窗口和换钥归单个异步 worker。
不导出密钥，不自行实现 DH、AEAD 或 Noise 握手。raw-split 是需要审查的集成边界，
不是向产品/UI 暴露原始密钥的公共 API。

维持当前 200ms 握手重试、5 秒建立期限、1200 字节包、1000 字节控制分块、
32 槽接收控制队列与 4 槽语音队列。ACK 只在保留控制块后发送；重传用新 nonce。
读超时/取消保留部分应用帧；已提交写被取消或超时关闭会话，避免半帧后继续复用。
收发公平调度，取消/维护期限先检查，网络写有界，不添加逐用户线程或 UI 轮询。
Rust library 使用调用方 Tokio runtime；暂不把实验 runtime 运行在 GPUI UI 线程。

## 生命周期与验收

Noise NK 完成仅表示传输认证；只有 signed Hello、合法 Welcome 和匹配 UID 才能
进入产品 connected 状态。密码/身份拒绝不能伪装为成功或自动重试未知结果命令。
已有资源/聊天失败与健康语音分离，重连恢复静音等产品约定均保持。

显式 close 必须取消等待并回收传输 worker，owner drop 也请求取消。最终进程内
核心不能依赖现有“750ms 后 kill 子进程”的回收边界；设备及原生调用必须单独
验证有界取消和迟到完成隔离，不能提前宣称当前退出保证自然继承。

验收依次覆盖真实 Go/Rust 互通、丢包重传、重放/篡改、换钥/确认/旧钥宽限、
背压、部分帧取消、密码/身份拒绝、退出及多平台构建；最后覆盖音频设备、多人长听
和 Windows 游戏负载。回环测试不代表 WAN、移动端或性能收益已验证。

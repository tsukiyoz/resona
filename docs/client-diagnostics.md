# 客户端断线与语音排查

问题出现后，在当前进程退出前，点击“语音与设备”设置右上角的向下箭头（导出诊断）。完成后自动定位 JSON 文件。导出位置：

- macOS：`~/Library/Caches/resona/diagnostics/`
- Windows：`%LOCALAPPDATA%\resona\diagnostics\`
- Linux：用户缓存目录下 `resona/diagnostics/`

默认不创建日志文件。内存只保留最多 512 条、最近 15 分钟的结构化事件；繁忙时保留时间可能短于 15 分钟。文件包含版本、平台、导出时间、容量覆盖次数和竞争丢弃次数。退出/崩溃后无法恢复未导出的记录。每次导出为独立文件，可手动删除；不自动上传，也不包含音频录制或聊天正文。

分享文件时附上大致故障时间、是否所有人都听不到、切频道或设备后是否恢复。音频累计计数在导出时补采；发送者细分与路由汇总为约 30 秒的活动窗口，最新不完整窗口可能尚未出现。汇总计数不是严格每 30 秒都有一条，静默时不会增加专用唤醒。

| 记录 | 解释 |
| --- | --- |
| connection / reconnect | 连接建立、断线、重试、恢复，包含退避时间和尝试耗时 |
| voice devices ready | 音频设备已就绪，是否采集、收听静音与发言模式 |
| voice configuration failed | 设备/语音配置失败，标记取消与超时类别 |
| voice routing interval | 收到的数据报、格式无效、成员/epoch 已过期、未安装音频处理器、交付给音频的数量 |
| voice counters | 当前音频运行累计接收、队列丢弃、发送交付数、发送错误及采集丢样 |
| voice peer interval | 当前时间窗口内各临时发送者 ID 的接收、解码、解码错误、抖动缓冲拒绝、成员未知与静音帧 |

路由收到了帧但没有交付音频，检查 stale/no_audio_handler；已交付但接收队列丢弃，检查本机处理是否滞后；特定 sender 持续 decode_errors，检查帧内容/编码链路；decoded 正常但 muted_frames 增加，检查单人音量及总收听音量。若 decoded 正常仍听不到，需要继续检查输出设备和混音链路，不能直接归因于网络。

`sent` 表示交给发送接口成功，不代表远端实际收到；`jitter_rejected` 包含重复或迟到帧，不等于公网丢包。安静时没有新日志不代表故障。发送者 ID 是临时会话标识，跨重连或复用不能直接视为同一个人。

重连只针对已经建立过的会话。明确认证失败停止重试，纯无响应继续可取消退避；当前约 30 秒无接收判定断线，之后退避间隔逐渐增至最多 30 秒。恢复后麦克风保持静音，避免误发言。客户端自动重连不需要升级 RN05 服务端。

# v0.0.3

Experimental native server administration and channel audio configuration.

- Persistent Ed25519 client identities, connection-bound identity proofs and
  one-time owner claims. Expired unused claims can be renewed offline; access
  directory locking prevents concurrent server/administration writes.
- Owner-only channel creation, editing and deletion, atomic persistence and
  capability-aware desktop context menus. Default and occupied channels cannot
  be deleted. Management requests do not block disconnect or shutdown.
- Channel audio presets: 20/32/48 kbps and custom integer 16..64 kbps. New channels
  default to 32; legacy channel settings retain 48. Encoder rate changes do not
  reopen devices or change mute/PTT state. Name, description and bitrate save
  together; older clients' metadata edits preserve the bitrate.
- `resona-core --version` and `resona-server --version` report version, source
  revision, dirty status and build time when supplied by the build.
- Includes the main-branch relay ring improvements, background Noise rekey,
  protobuf control messages and credential improvements since v0.0.2.

## Upgrade and Limits

Native transport versions are Noise exp-4 / QUIC exp-3. Upgrade clients and servers
together from v0.0.2; incompatible older native versions do not silently fall back.
Back up the server identity and access directory before upgrading. Never replace
the existing owner record or private key as part of a normal upgrade. See
[server administration](../server.md) for claim and persistent-channel operations.

Audio quality support is separately advertised: a compatible server lacking that
capability still permits supported metadata edits. Older clients do not adopt a
new encoder policy automatically. Bitrate is a VBR target excluding network
overhead, not congestion control or a server-enforced bandwidth limit.

Go core/integration/race checks, both native transports, Rust desktop tests and
local macOS channel workflows passed; details are in [verification](../verification.md).
Windows packaging runs on the release tag, and Windows device/listening acceptance
remains separate. The protocol is experimental; no independent security audit,
adaptive voice congestion control, fine-grained permission system or music/stereo
channel mode is claimed. This tag does not deploy the remote server.

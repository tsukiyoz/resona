## UI 04：MineRadio 风格比较稿

磨砂二次调整：用户认为色调偏亮、透明不明显。主背景改为近中性黑 `#050607` 至 `#101112`，去除表面的蓝灰倾向；弹层支持背景滤镜时底色透明度降为 60%，模糊增为 22px，同时减轻遮罩，让底下频道和聊天内容透出模糊轮廓。工具栏以静态透光边缘和细微反光体现质感，不新增常驻模糊。无滤镜支持或偏好减少透明度时用深色实底，布局不变。

质感补充：用户认可紧凑语音工具栏后要求半透明磨砂。增加静态斜向底色、半透明表面与细微内高光；仅设置/资料弹层使用 14px 背景模糊，常驻聊天、侧栏和语音栏不做实时模糊。减少透明度偏好下弹层使用实色。不新增动画或改变布局。此为 HTML 视觉原型，GPUI 实现的 GPU/功耗开销尚未验证。

最新反馈：用户认可设置页，但认为悬浮底栏过于像音乐播放器。底部已改为 72px 全宽语音工具栏，左侧本人和状态，右侧同尺寸的静音/收听/设置图标、音量滑块及离开入口；取消居中大按钮和悬浮胶囊。设置页视觉不变，小屏仍在设置中调整音量，资料层和导航下边界同步为 72px。以下播放器式方案仅保留为历史说明，已被此修订替代。

第二次修订：用户指定的原仓库是 [XxHuberrr/Mineradio](https://github.com/XxHuberrr/Mineradio)，此次核对提交 `328a087a14e79d5267a3de54d29108c34ed6cf60` 的 `public/index.html` 与 `public/css/index.css`。上一稿使用另一 fork 的样式，仅形成换肤，未达到用户预期。原仓库当前播放控件为黑白半透明风格，底栏中轴固定、左右等宽弹性排列。新增 `mineradio-stage.css` 重排为无多层标题的开放聊天、无边框侧栏和底部居中控制台；收听音量移入设置。没有引入背景动画或复制其音乐业务。仅源码及构建复核，不声称已运行原软件或完成截图验证。

用户暂缓 desktop 迁移，要求先比较 MineRadio 风格。运行 `node docs/ui-prototype/build.mjs mineradio` 生成 `mineradio.html`；新增样式变体 `mineradio.css`，复用已确认的聊天交互，保留 UI 03。

参考 [MineRadio 公开样式](https://github.com/oirge/Mineradio/blob/main/public/app.css) 的近黑底色、冷白文字、青色操作、香槟色与珊瑚红辅助色。以开放聊天区、减弱分隔和播放器式固定语音控制作 Resona 适配，不引入持续粒子渲染、背景视频或实时玻璃滤镜。此稿不是 MineRadio 界面的一比一复刻。

验收沿用聊天主视图、频道内小型成员、查看/加入分离、固定底栏和关闭设置停止试听演示。900×600 与移动断点需检查无横向溢出、抽屉上下边界和静音/耳聋状态对比度。独立 HTML 构建及 React 静态渲染已通过，初始页包含聊天、语音栏与示例标识且没有成员卡片；尚未完成浏览器截图与真实交互验收。此前浏览器工具禁止本地 file 页面，本次未绕过限制。

## UI 03：暗色语音房间

最新反馈调整：取消语音房间入口及大头像区，暗色版只展示频道聊天；左侧频道树保留成员与资料入口，底栏保留语音操作。加入等待期间禁止发送，草稿仍可编辑并按频道保留。下述语音成员项方案已被用户否定，不作为实现依据。

默认页改为语音成员项，不再用后台表格、身份/操作列或分页。中性炭灰 `#18191d` / `#202126`，成员项 `#24262d`，主操作青绿 `#88d9c0`；头像使用低饱和多色区分成员，不使用常驻光效、模糊或装饰动画。宽屏四列、普通窗口两列，固定语音底栏，资料抽屉与设置保持原交互。

成员项只显示静音、收听及演示状态，不模拟正在发言或音频电平。耳聋显示“收听与发送已暂停”，PTT 释放态显示“等待按键”。静态 React 渲染通过，确认初始页为语音成员区且不含表格；尚未完成浏览器截图验收。

## UI 02：Ant Design 风格

用户认为 UI 01 与旧界面区别不足，新增独立 `antd.jsx` / `antd.css`。运行 `node docs/ui-prototype/build.mjs antd` 生成 `antd.html`。这是风格原型，未引入 Ant Design 到 GPUI，也未增加 Wails 功能。

UI 02 默认浅色，采用白色顶栏、浅灰工作背景、240px 左导航、成员表格优先的工作区、独立聊天标签、按需资料抽屉、标准表单弹窗。蓝色操作、绿色状态与中性色分隔遵循 Ant Design 常见视觉语言。与 UI 01 的常驻三栏聊天结构不同。

单击频道只看资料，双击/Enter/加入按钮才变更当前频道；加入等待、取消、失败保留原频道；聊天草稿按频道保留。资料抽屉不遮挡语音底栏，设置关闭停止试听演示。初始页面通过静态 React 渲染检查；未完成浏览器截图与实际交互验收。当前工具阻止 file:// 页面，未绕过限制。

2026-09-10 的交互原型，供 0.0.2 UI 方向评审。当前未替换 GPUI，也不另行维护一套产品前端。

## 设计方向

参考 [GPUI 应用示例](https://gpui-kit.com/zh-CN/apps/) 中 Longbridge Pro 的紧凑分区，结合 Ant Design 风格的表单、间距和蓝色操作态。深色为中性石墨灰，浅色为白色工作区与浅灰侧栏；避免常驻动画、模糊和大片装饰。现有 Resona 位图标识继续使用，按钮统一 Lucide。

- 工作区：252px 频道树 / 可伸缩聊天 / 274px 可收起资料栏。
- 底栏：本人身份、麦克风、收听、音量、设置和离开状态固定可达。
- 设置：左侧分类、右侧分组表单；设备用菜单，激活方式用分段控件，数值用滑块，二元设置用开关。
- 字体：沿用系统中文 UI 字体；主要标题 18-23px，正文 13px，辅助信息 11px，数值使用等宽数字。
- 颜色：深色背景 `#181a1d`、分区 `#1e2024`、正文 `#e6e8eb`、操作 `#69a9ff`、频道状态 `#68c7a9`、预览 `#d9b16d`；浅色操作色 `#1677ff`。

## 预览

仓库已有 frontend 的依赖时运行：

```sh
node docs/ui-prototype/build.mjs
```

生成 `index.html`，浏览器直接打开即可。JS、CSS、图标与应用标识均内嵌，不访问 CDN。源码复用已安装的 React/Lucide/esbuild 作为原型工具；这些不是 GPUI 的运行依赖。生成 HTML 与截图不进入 Git。

支持：深浅主题、频道搜索、单击资料、双击/Enter/按钮加入、等待取消/权限拒绝演示、成员资料、分频道本地草稿和消息、静音/收听、音频设置、试听等待/停止/失败演示、离开和结束预览。

示例成员与消息均为原型数据。没有 TS3 连接、麦克风采集、音频播放、系统快捷键注册、凭据保存或客户端配置写入。电平为未采集状态，不展示伪造读数。添加服务器表单只预览，不保存；不把该原型当作这些功能的集成验收。

## Open Design 评估

本机安装 Open Design 0.22.0，首次尝试通过桌面接口打开超时，未完成实际画布或 MCP 端到端试用。不能据此判定其稳定性或设计质量差。

根据[官方仓库](https://github.com/nexu-io/open-design)，它适合管理设计系统、代理生成、可交互预览和 HTML/PDF/PPTX/MP4 导出；MCP 可供外部代理访问项目与产物。本轮建议暂不作为必需工具：Resona 的交付仍是 Rust GPUI，HTML 原型需要按原生组件重建，不存在已经验证的 GPUI 直接导出链路。本次独立 HTML 已能评审布局与状态，接入成本暂时没有明确收益。后续若需要批量风格方案、复用设计系统或跨项目资产管理，再做一个小样实测其价值。

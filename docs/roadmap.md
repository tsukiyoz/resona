## M1：真实 TS3 协议验证

目标：决定采用、修补或替换现有 Go 协议库。

当前先完成只读切片：GUI 连接/断开、持久身份、服务器推送的初始频道树和可见成员。主动 `channellist` 查询曾返回 2568，因此改用普通客户端登录推送，不要求提升服务器权限。文字、语音、完整故障矩阵仍待验证，M1 整体未完成。详情见 [验证记录](verification.md) 和 ADR-0005。

后续进展：已接入 GUI 无密码频道切换、权限拒绝、单次移动和断开取消；实际会话服务成功进入 Resona 自建临时测试频道，夹具退出后已核对频道删除。前端操作由 mock bridge 回归验证，原生窗口完整点击流程仍受工具识别问题影响，未单独声称通过。设计见 ADR-0006。

用户随后手动体验了当前桌面版本并反馈可接受。继续接入当前频道成员进出、自身断开的本地提示音及设置；协议事件、会话通知队列与 GUI 播放分层，设计见 ADR-0007。提示音不代表语音通话或音乐机器人已完成，实际成员进出到本机扬声器的整条链路仍需专用频道验收。

最新反馈推进频道树成员展示、长列表滚动、成员订阅状态、双击或 Enter 进入服务器，以及 macOS 钥匙串记住密码。双击使用已保存凭据直连，切换服务器先准备凭据再断旧连新，仍为单一会话。实现与产品验收见 ADR-0008 和 [功能设计](product.md)。本轮本地 Go race 与 29 项前端回归已通过；原生钥匙串和专用频道真实成员验证尚在推进，不能用本地回归代替这两项验收，最新结果以 [验证记录](verification.md) 为准。

- 固定候选库 commit，审查身份、握手、加密、超时和关闭路径。
- 生成并安全保存独立的机器人/客户端身份，验证重启后 UID 一致。
- 在获准使用的测试 TS3 服务器连接、列出频道/用户、收发文字和切换频道。
- 发送固定本地音频，并用官方客户端听取；接收官方客户端语音并解码播放。
- 覆盖错误密码、无权限、踢出、网络中断、重连、主动关闭和高身份安全等级要求。
- 记录依赖的 native codec / audio device 能力，区分协议库和完整音频链路。

验收产物：可复现的集成测试说明、版本兼容矩阵、日志、长连接与资源释放结果，以及协议选型 ADR。没有目标服务器和测试身份时，该阶段不能标记完成。

## M2：可日用 GUI 客户端

产品体验待完善：本人切频道成功反馈、主动断开与异常掉线的反馈区分、逐类提示音开关；私聊和静音状态提示随对应功能一并设计。本次先补本人成功连接服务器的提示音，其他项目仍待实现与验收。

- 服务器书签连接与 macOS 系统钥匙串密码保存已进入当前实现；继续验证原生凭据全流程，身份选择和其他平台凭据存储待后续。
- 频道树与授权可见成员的展示、滚动和订阅状态已进入当前实现；继续验证真实成员变化，频道与私聊消息、自动重连待后续。
- 麦克风/输出设备选择，静音、耳聋、音量、按键发言与语音激活。
- 音频接收缓冲、解码、多人混音，验证持续播放和设备切换。
- 中文界面、键盘导航、可访问性、浅/深色主题与平台安装包。

验收：用户可以替代日常 TS3 客户端完成约定核心工作流；未支持的 TS3 功能逐项列出，不能笼统声明完全兼容。

## M3：扩展与无界面机器人

- 先用内置音乐扩展验证事件订阅、命令注册、消息发送和音频注入接口。
- 同一 Go 客户端核心用于 GUI 和独立机器人入口。
- 拟定扩展能力、生命周期、版本和错误模型；插件不得绕过核心持有连接或身份私钥。
- 根据真实扩展需求引入进程隔离、权限授予和第三方 SDK。

验收：音乐扩展和一个自动化机器人通过同一扩展边界工作；禁用扩展会释放订阅和资源；失败不会破坏核心会话。

## M4：兼容服务端研究原型

- 明确首个兼容目标为特定版本普通 TS3 客户端的基本连接、频道、消息和语音。
- 实现服务端握手、会话、频道状态、权限、语音路由和持久化。
- 使用官方客户端、Resona 客户端交叉验证，不只验证自家两端。
- 将自有扩展通过能力协商接入；不能破坏约定的 TS3 基础兼容行为。

验收：公开兼容矩阵与已知差异，完成权限隔离、资源限制和故障恢复验证。高可用、联邦、大规模集群均不在首个原型范围。

## 当前明确不做

- 不为尚不存在的服务端创建空微服务或通用基础设施仓库。
- 不把 TS3AudioBot HTTP API 固化为客户端核心模型。
- 不在启动时自动连接任意地址或采集麦克风；密码只在用户启用记住密码且认证成功后写入系统钥匙串，浏览器预览不保存密码。
- 不提前承诺第三方协议库的语音接收、平台覆盖或商业授权结论。

# 推进计划

日期：2026-09-07。阶段顺序依据依赖与可验证性排列，不预估尚未探明的协议工作量。

终点是自有客户端、服务端和 Go 插件/机器人生态。TS3 是第一种兼容协议；将来的客户端和服务端需要各自验证 TS 互通。是否增加自研协议取决于测得的功能、性能和维护限制，不以提前替换协议为目标。

## M0：桌面基础

目标：可构建的 GUI 客户端骨架和明确的工程边界。

- [x] 确定单仓库、单 Go module 的起点。
- [x] 明确 GUI 优先，选择 Wails v2 + React/TypeScript。
- [x] 建立架构、功能、计划和 ADR 文档。
- [x] 完成服务器书签 CRUD 与原子持久化。
- [x] 完成本地频道和聊天预览，持续显示预览状态。
- [x] 完成前端构建、Go 测试与 macOS 原生构建验证。
- [x] 完成桌面与窄屏布局检查。

验收：全新配置可启动；书签在重启后存在；损坏配置不被覆盖；预览不产生真实 TS3 连接；界面错误可见。当前 macOS 为开发验证平台，Windows/Linux 尚不声明已验证。

## M1：真实 TS3 协议验证

目标：决定采用、修补或替换现有 Go 协议库。

当前先完成只读切片：GUI 连接/断开、持久身份、服务器推送的初始频道树和可见成员。主动 `channellist` 查询曾返回 2568，因此改用普通客户端登录推送，不要求提升服务器权限。文字、语音、完整故障矩阵仍待验证，M1 整体未完成。详情见 [验证记录](verification.md) 和 ADR-0005。

后续进展：已接入 GUI 无密码频道切换、权限拒绝、单次移动和断开取消；实际会话服务成功进入 Resona 自建临时测试频道，夹具退出后已核对频道删除。前端操作由 mock bridge 回归验证，原生窗口完整点击流程仍受工具识别问题影响，未单独声称通过。设计见 ADR-0006。

用户随后手动体验了当前桌面版本并反馈可接受。继续接入当前频道成员进出、自身断开的本地提示音及设置；协议事件、会话通知队列与 GUI 播放分层，设计见 ADR-0007。提示音不代表语音通话或音乐机器人已完成，实际成员进出到本机扬声器的整条链路仍需专用频道验收。

频道树成员展示、长列表滚动、成员订阅状态、双击或 Enter 进入服务器，以及 macOS 钥匙串记住密码已随 `268b528` 交付，用户确认验收。原生钥匙串和专用频道成员验证证据见 [验证记录](verification.md)，产品与设计见 ADR-0008。

频道纯文本收发、发送状态与显式重试、断线只读记录、TS spacer 归一化和自定义图标下载已接入。Go 并发测试、前端回归、桌面构建、专用频道真实文字往返，以及服务器全部 22 个频道图标加载复验已通过；新版用户桌面验收待进行。设计见 ADR-0009。文字历史只在本次连接内保存，私聊、富文本和跨应用重启历史不进入本轮。

- 固定候选库 commit，审查身份、握手、加密、超时和关闭路径。
- 生成并安全保存独立的机器人/客户端身份，验证重启后 UID 一致。
- 在获准使用的测试 TS3 服务器连接、列出频道/用户、收发文字和切换频道。
- 发送固定本地音频，并用官方客户端听取；接收官方客户端语音并解码播放。
- 覆盖错误密码、无权限、踢出、网络中断、重连、主动关闭和高身份安全等级要求。

验收产物：可复现的集成测试说明、版本兼容矩阵、日志、长连接与资源释放结果，以及协议选型 ADR。没有目标服务器和测试身份时，该阶段不能标记完成。

## M2：可日用 GUI 客户端

2026-09-09：完成 macOS release 常驻比较，并纠正了界面观察工具恢复最小化窗口的测量干扰。真正最小化时原生唤醒降至约 0.30 次/秒，详见 wakeup-investigation.md。新 GUI 功能集中 GPUI，Wails 冻结为回退基线（ADR-0015）。后续补 Windows 同负载语音/游戏测量，不据空闲数据勾选最终迁移。

2026-09-08 当前开发切片：GPUI 原生桌面 + Go 子进程控制 + 双向 Opus 语音。用户追加本期范围：自动收听且默认关闭麦克风、本地麦克风试听、PTT/持续传输/阈值检测、SpeexDSP 回声消除与分级降噪、本应用收听闪避、频道/用户详情、独立图标资源及有界优雅退出，见 ADR-0013 / ADR-0014。实现、合成测试、设备听测和游戏负载分别验收；Windows 必须单独验证。保留 Wails 基线，不把代码可编译等同于语音互通或低资源目标达成。

下一步优先建立 release 桌面资源基线，并验证同负载原生 UI 小样，评估 GPUI + GPUI Kit / Slint 与 Go 核心复用。性能目标覆盖游戏期间的后台 CPU、全进程内存和 GPU 干扰，不以安装包大小代替运行成本；详细方案见 [桌面 UI 评估](frontend-evaluation.md)。框架迁移仍待证据与新 ADR。

当前切片补充图标的有限内存 -> 磁盘 -> 网络读取，支持跨重连和重启复用（ADR-0010），并将 GUI 调整为参考 Oopz 信息层级的紧凑石墨深色界面，保留可选浅色主题与已有用户偏好。缓存验证与桌面外观验收分别记录于 [验证记录](verification.md)，不据此标记整个 M2 完成。

产品体验待完善：本人切频道成功反馈、主动断开与异常掉线的反馈区分、逐类提示音开关；私聊和静音状态提示随对应功能一并设计。本次先补本人成功连接服务器的提示音，其他项目仍待实现与验收。

- 服务器书签连接与 macOS 系统钥匙串密码保存已进入当前实现；继续验证原生凭据全流程，身份选择和其他平台凭据存储待后续。
- 频道树与授权可见成员的展示、滚动和订阅状态已经验收；频道纯文本与图标/spacer 进入当前切片，私聊、富文本、持久历史和自动重连待后续。
- 麦克风/输出设备选择，静音、耳聋、音量、按键发言与语音激活。
- 音频接收缓冲、解码、多人混音，验证持续播放和设备切换。
- 中文界面、键盘导航、可访问性、浅/深色主题与平台安装包。

验收：用户可以替代日常 TS3 客户端完成约定核心工作流；未支持的 TS3 功能逐项列出，不能笼统声明完全兼容。

## M3：扩展与无界面机器人

- 先用内置音乐扩展验证事件订阅、命令注册、消息发送和音频注入接口。
- 同一 Go 客户端核心用于 GUI 和独立机器人入口。
- 拟定扩展能力、生命周期、版本和错误模型；插件不得绕过核心持有连接或身份私钥。
- 根据真实扩展需求引入进程隔离、权限授予和第三方 SDK。

验收：音乐扩展和一个自动化机器人通过同一扩展边界工作；禁用扩展会释放订阅和资源；失败不会破坏核心会话。

## M4：兼容服务端研究原型

- 明确首个兼容目标为特定版本普通 TS3 客户端的基本连接、频道、消息和语音。
- 实现服务端握手、会话、频道状态、权限、语音路由和持久化。
- 使用官方客户端、Resona 客户端交叉验证，不只验证自家两端。
- 将自有扩展通过能力协商接入；不能破坏约定的 TS3 基础兼容行为。
- 客户端与服务端保持各自的业务权威边界，只共享经过互通验证的协议组件和一致值类型。

验收：公开兼容矩阵与已知差异，完成权限隔离、资源限制和故障恢复验证。高可用、联邦、大规模集群均不在首个原型范围。

## 后续协议演进

- 记录 TS 兼容协议在功能、端到端延迟、可靠性和维护成本上的实际限制。
- 有明确收益时再提出自研协议 ADR，定义版本协商、迁移和客户端/服务端交叉测试方案。
- 保留经过验证的 TS 兼容适配，不把自研协议可用等同于 TS 兼容完成。

## 当前明确不做

- 不为尚不存在的服务端创建空微服务或通用基础设施仓库。
- 不把 TS3AudioBot HTTP API 固化为客户端核心模型。
- 不在启动时自动连接任意地址或采集麦克风；密码只在用户启用记住密码且认证成功后写入系统钥匙串，浏览器预览不保存密码。
- 不提前承诺第三方协议库的语音接收、平台覆盖或商业授权结论。
